# n64ps3 Gap Report

This report tracks the runtime and graphics work needed to move from the
synthetic smoke task and original Arwing asset harness toward the Star Fox 64
title-screen display lists.

## Current Graphics State

- Host builds select `rdpnull`, which decodes and logs the synthetic task's
  F3DEX1 command statistics.
- PSL1GHT Makefile builds select the `rdprsx` backend. It initializes an RSX
  context, uses the current video mode, allocates two XRGB framebuffers and a
  24-bit depth / 8-bit stencil buffer, clears to black (the title's initial
  `gBgColor`), and presents with synchronized flips. `Z24S8` is enabled, but
  the user confirmed that the static Arwing's surfaces are stable at 60 Hz
  after the backend began waiting for prior flips before reusing buffers.
- The portable decoder handles big-endian F3DEX1 `VTX`, `TRI1`, `TRI2`, nested
  `DL`/`ENDDL`, segment bases, `MTX`/`POPMTX`, directional/ambient lights,
  geometry mode, and the Arwing's RGBA16 `SETTIMG`, `SETTILE`, `LOADBLOCK`, and
  `SETTILESIZE` commands. It decodes fixed-point matrices, tracks an 18-entry
  modelview stack, emits transformed clip coordinates, and captures texture UVs,
  tile dimensions/origin, masks, shifts, and wrap modes per
  triangle. It also handles RGBA5551
  `SETFILLCOLOR` and 320x240 `FILLRECT` commands as screen-space triangles for
  the title starfield. Display-list, matrix, light, and texture data resolve
  through bounded task RDRAM. Sync commands are no-ops; other fixed-width
  commands remain unsupported.
- `rdprsx` collects decoded triangles into RSX-resident vertex/index buffers
  and submits clip-space coordinates, vertex-light colors, and texture UVs. It
  converts original RGBA16/RGBA32 texture blocks to ARGB8888 RSX textures, applies
  tile wrapping, and uses the title's texture-times-shade combination. Per-
  triangle geometry mode is preserved; `G_ZBUFFER` and cull bits configure RSX
  depth and face culling. The decoder also carries `FORCE_BL` from
  `SETOTHERMODE_L`, and `rdprsx` uses it to blend title-logo texture alpha.
  General combine modes, other RDP render-mode rules, alpha test, fog, and
  framebuffer effects are still unsupported.
- The SF64 smoke task contains a ROM-free synthetic segmented display list with
  one nested list, one vertex load, and one triangle. It validates task memory
  resolution and the path into `rdprsx`; it is not generated by the original
  game.
- A separate title-scene harness extracts US Rev 1 `ast_arwing` and `ast_title`
  banks from the user-provided local ROM at build time. The PS3 path initializes
  title state with the game's skip flag set, then preserves the original
  `OvlMenu_CallFunction(OVLCALL_TITLE_UPDATE, NULL)` dispatch boundary into
  `Title_Main()` and `Title_Setup()`. Per-frame updates use that same overlay
  dispatch and reach `Title_UpdateEntry()`, `Title_Screen_Update()`,
  `Title_Screen_Setup()`, and title input logic. A quiet virtual controller
  port supplies zero input; audio commands
  are inert. The original SF64 seeded starfield generator and background
  traversal also run from a local source checkout. Rendering still uses a
  custom task builder that parses the original Arwing skeleton and the
  `aAwWingsClosedAnim` pose selected by the title's `GSTATE_TITLE` branch,
  recreates the title camera/light, and emits a root list
  calling the original body and wing display lists. The host probe validates
  18 limbs, 9 Arwing lists, 456 stars in frame one and 457 in frame two, then
  decodes both tasks with zero skipped commands. The second task has 1,730
  commands and 1,088 triangles, including 174 textured Arwing triangles. The
  probe confirms stable texture-source hashes and texture-coordinate/tile state
  across those frames, with at most a one-byte vertex-shade change. It still
  bypasses outer `Game_Update()` setup/scheduling and does not execute the
  original `Game_Draw()` path. `OvlMenu_CallFunction()` is extracted and the
  harness enters its title-draw case through the original `gDrawMode` gate. A
  title-state shim calls the original `Title_StarfoxLogo_Draw()`; its 30 RGBA16
  strip requests are adapted to F3DEX1 quads using the embedded segment-6 data.
  The rest of the original draw body / `Title_Screen_Draw()` remain unexecuted;
  team, copyright, and PRESS START remain absent. The player-movable 3D `64`
  object is separate from the captured Star Fox logo strips and is not part of
  this adapter. The original PRESS START IA8 mask is expanded to RGBA32 with
  PSP-style soft coverage and RSX bilinear filtering.
- `make ps3-arwing-self` embeds the extracted banks and generated original
  source only in ignored `build/arwing/` output. Set `SF64_SOURCE_DIR` when the
  local SF64 source checkout is not at `../sf64-psp`. This harness does not boot
  the original game loop or introduce a general ROM/DMA provider in `n64ps3`.
- The RSX textured path uses the existing vertex and fragment programs to pass
  vertex attributes and compute texture-times-shade output with the sqrt RGB
  transfer. The first Cg gamma build produced magenta output because the
  installed `cgcomp` did not relocate temporary `R0` away from RSX's COLOR
  output register. The current fragment program uses explicit assembly with
  scratch register `R1` and reserves `R0` for output. Its assembled microcode
  passes 582 color/alpha cases; the previous program fails the same check.
  Assembly needs no Cg runtime. High-level vertex shader regeneration still
  uses the official NVIDIA package extracted under ignored
  `build/toolchain/nvidia-cg-3.1/`. The SDK register-allocation and blank-line
  parser defects are documented in [RSX shader toolchain findings](RSX_SHADER_TOOLCHAIN.md).
- Renderer initialization status propagates through `n64ps3_runtime_init()`.
- A host smoke regression found and fixed duplicate VI event delivery: the
  retrace helper now delivers through the registered `OS_EVENT_VI` binding.

## APIs Successfully Used

- `n64ps3_config_default`, `n64ps3_runtime_init`,
  `n64ps3_runtime_shutdown`
- `osCreateMesgQueue`, `osViSetEvent`, `n64ps3_vi_raise_retrace_for_host`,
  `osRecvMesg`
- `n64ps3_pad_init`, `n64ps3_pad_read`
- `n64ps3_gfx_begin_frame`, `n64ps3_gfx_submit_task`,
  `n64ps3_gfx_end_frame`
- `n64ps3_gfx_decode_f3dex1` for a small host-validated command subset
- `n64ps3_pi_read_rom` exists, but there is no ROM-free asset provider.
- `sf64_arwing_build_title_task` in this repository builds a game-specific
  display-list task from the original ROM bank; this is a diagnostic consumer,
  not an `n64ps3` runtime API.

## Missing for Original Title Rendering

1. Broader viewport/RSP state. FILLRECT uses a fixed 320x240 logical viewport;
   VI mode and viewport/scissor commands are not connected to the renderer.
   Matrix results need more comparisons against original game lists.
2. General RDP state translation for combine modes, non-RGBA16 texture formats,
   detailed filtering, alpha test and blend variants, fog, depth compare/update rules, scissor, and
   framebuffer effects. The current textured path implements the one
   texture-times-shade setup used by the title Arwing.
3. Broader microcode and display-list support beyond the F3DEX1 smoke subset,
   including the original game's command sequences and unsupported-command
   semantics.
4. Validate correct material output and the N64 VI approximation. The RSX
   shader now applies the PSP reference's sqrt-based RGB transfer; VI gamma
   dithering remains unimplemented and the updated image needs confirmation.
5. A runtime PI/DMA asset loading path for the original title, Arwing, team,
   and shared graphics data. The title-scene SELF currently embeds one
   build-time asset bank and is not a reusable asset provider.
6. The libultra/runtime calls required to run `bootproc`, the main thread,
   scheduler, PI/DMA asset loads, controller input, timers, and game tasks.
7. Full original title draw execution. The harness enters the overlay draw
   dispatch, checks title-state gates, and calls the original Star Fox logo
   subroutine. It still skips `Game_Draw()` setup and the rest of `Title_Draw()`
   / `Title_Screen_Draw()`. The team and remaining UI need the game's
   `gMasterDisp` command-list path, matrix/light state, skeleton traversal, and
   IA8/CI8/TLUT texture-rectangle calls.
  The logo adapter combines three neighboring 2-row strips per draw region and
  pads each interior tile with the adjacent source rows for bilinear filtering;
  the PS3 backend accepts 256-pixel textures and has a 64-entry texture table. The user
  confirms the 2D title layer now preserves its 4:3 aspect on a 16:9 display.
  The user reports that `SETUPDL_83` texture-alpha blending did not remove the
  logo seams; clamp-to-edge improved them but left small seams. The latest
  build adds adjacent-row filter guards, pending RPCS3 visual confirmation.

The user reports that the standard triangle and Arwing SELF run in RPCS3. Their
latest pre-transfer screenshot confirms the black clear, original Arwing
geometry and texture detail, and original-source starfield, but shows a dark
Arwing. A prior gamma shader experiment made it magenta and was reverted; the
current shader applies the PSP reference's sqrt-based RGB transfer, pending a
new image. VI gamma dithering remains unimplemented. The first textured build
crashed because its RSX texture descriptor had zero mip levels; the initializer
now sets one base level. No PS3 hardware result has been reported. Team/title
graphics, broader RDP state, and the original game loop remain incomplete.

The static SELF log sampled 34 frames from frame 0 through frame 3480. Every
sample had identical textured-triangle position, shade, UV, binding, RGBA16
source, and converted-texture hashes (`pos=efe122d4`, `shade=3fba375f`,
`uv=83ce7568`, `bind=44561cd3`, `source=842ab188`, `upload=68e0e5b8`; 174
textured triangles, 14 textures). The user then confirmed that textures are
stable and updates are smooth at 60 Hz in the static build with the flip wait.
This supports the diagnosis that the RSX vertex/index buffers were reused
before the previous flip completed. The previous Arwing capture remains dark;
the sqrt transfer needs visual confirmation. Broader N64 RDP combiner,
render-mode, alpha, fog, and VI dithering support are still needed.
The depth-disabled SELF is at
`build/arwing-nodepth/ps3/sf64_ps3_arwing_nodepth.self`.

`make ps3-arwing-static-self` builds a second diagnostic at
`build/arwing-static/ps3/sf64_ps3_arwing_static.self`. It preserves the
original title update and starfield while holding the Arwing's X rotation at
35 degrees. The user's first run crashed in `Animation_GetFrameData` during
`Title_Screen_Setup`: the extracted N64 animation record used `u32` fields,
but that header typedef is 64-bit `unsigned long` in the PPU build, shifting
the two segmented pointers from N64 offsets 4/8 to PPU offsets 8/16. The
extractor now uses `uint32_t` for those asset fields. The rebuilt SELF's
disassembly confirms 32-bit loads at offsets 4 and 8. The user ran the
flip-wait-enabled static-pose SELF and confirmed stable textures and smooth
60 Hz updates. The latest regular and static SELFs preserve the original title
update overlay dispatch and use the title's closed-wing animation; both builds
completed, but neither has a new RPCS3 run yet.

The SF64-PSP source and US Rev 1 asset metadata identify segment 3's ROM base
as `0x8BFC00`. The body display list is at segmented address `0x03009B60`, and
the right-wing list is at `0x03015D80`; the skeleton is at `0x03016610` and the
left-wing list at `0x03016660`. The local ROM is ignored by Git. The host probe
reports 174 original triangles across 9 skeleton display lists. Do not copy
the ROM or generated assets into source control.

## Runtime Gaps

- `osSendMesg` and `osRecvMesg` exist, but ignore `OS_MESG_BLOCK` and do not
  implement `osJamMesg`.
- VI smoke delivery is deterministic through a manual helper. A real
  backend-driven retrace cadence is not implemented.
- `n64ps3_pad_read` currently returns a zeroed state; it does not provide PS3
  pad input or libultra controller compatibility.
- PI reads are ROM-only. There is no ROM-free file/asset provider or DMA
  abstraction.
- Audio submission and completion are not implemented.
- Graphics tasks carry display-list/RDRAM mapping data, but there is no SP/DP
  scheduler or task completion signalling.
